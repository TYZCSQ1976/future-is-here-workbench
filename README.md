# 🚀 未来已来 · 本地 AI 工作台

> 一个在本地浏览器运行的开源 AI 团队协作平台——Claude Code、Codex 和 DeepSeek Harness 在这里等你指挥。
> 产品服务和会话文件默认只在本机运行；发送给 Claude/Codex/dsh CLI 的提示词仍会遵循对应 AI 服务的网络与隐私规则。

这是一个**本地优先的单用户开源项目**：每位使用者在自己的 Mac 上启动自己的服务，使用自己的 AI CLI、凭据、任务数据和工作目录。本项目当前不提供远程多用户服务，也不建议把本地端口直接暴露到互联网。

---

## 📖 项目简介

「未来已来」是一个纯本地的 AI 工作台网页应用。它的核心价值是：

- **多 AI 对话**：同一个问题先让 Claude、Codex、DeepSeek（dsh）并行独立回答，谁先完成就先展示；也可以让多方再互相确认一次
- **多 AI 协作**：多个 AI 可以像真实团队成员一样讨论方案、互相审查、分工合作
- **证据化协作**：事实、假设、风险、验收标准和缺失证据都进入机器可校验的结构
- **长程检查点**：每一轮提案、审查、执行和验证都持久化，任务状态不只存在于页面里
- **多任务并行**：一个 AI 在后台思考时，你可以自由切换到其他任务，互不阻塞
- **本地优先**：任务状态和会话文件保存在本机，不依赖本项目自己的云端数据库；AI CLI 是否联网由对应 Provider 决定

打个比方：它不是一条永远固定岗位的流水线，而是一间可以临时组队的 AI 会议室。你可以为同一个任务安排多个 Claude/Codex/DeepSeek 分身，临时决定谁负责产品、工程、安全、验证或主笔；他们可以互相点名提问、质疑、回应并保留分歧。

## ✨ 功能特性

### 💬 对话模式
- Claude、Codex、DeepSeek（dsh）均可独立勾选，支持任选其中 1 个、2 个或全部；“全选”只是快捷操作
- 多 AI 可选“互相确认（更可靠）”或“独立并行（更快）”；默认先独立回答，再进行一轮有界互证；未安装的 Provider 会被明确跳过，不再拖垮整轮任务
- 每个成员的运行、完成和失败状态分别显示；任一成员超时不会吞掉其他成员已经完成的回答
- 对话、讨论、协作共享同一任务最近 20 条历史，并标注每条内容来自哪种模式；讨论方案和协作审批仍按专用状态保存
- 文件夹作为“参考资料”上传：每个任务原文件合计 100MB，使用 4MB 二进制分块续传；文字、代码、JSON、CSV、PDF（文字型）和 DOCX 可提取，AI 每轮只接收与问题相关的片段
- Markdown 富文本渲染（标题、列表、代码块、表格、引用、图片等）
- 代码块一键复制按钮
- XSS 防护（所有 AI 返回的内容经过 DOMPurify 消毒）

### 🧭 方案讨论
- 使用与协作相同的动态团队、角色、多轮质疑和共识机制，但讨论结束后不会直接执行
- 方案及审查证据持久化到当前任务
- 点击“导入协作并准备实施”会创建一个独立实施任务，避免讨论记录和执行状态混在一起

### 🤝 协作模式
四种协作模式现在只是“会议方法”，不再固定任何 Provider 的角色：

| 方法 | 作用 |
|------|------|
| **开放共创** | 鼓励多个方向并行探索和比较取舍 |
| **严格评审** | 集中寻找 bug、漏洞、边界和测试缺口 |
| **对抗推演** | 主动构造反例、攻击路径和防御绕过 |
| **动态分工** | 围绕本次团队讨论职责、接口和合并验收 |

每个任务都可以配置：

- 2—6 个智能体实例，同一个 Claude/Codex/DeepSeek 可以开多个独立分身；
- 每个分身的名称、临时角色和重点关注；
- 本次负责汇总方案的主笔人；
- 1—5 轮交叉对话；
- 全体确认、多数确认或“保留分歧，由我决定”。
- 既可以由你手动组队，也可以让 Claude、Codex 或 DeepSeek 先按当前目标建议团队，再由你编辑确认。
- 你可以看到每个成员底层由 Claude、Codex 还是 DeepSeek 承担；参会成员只看到中性编号、会议姓名和本次角色，不会收到 Provider 对照表。

**协作流程**：
```
你配置本次团队并用 cd 绑定工作目录 → 所有分身独立思考（互不可见）
→ 后续轮次互相点名 question / answer / challenge / agreement
→ 你指定的主笔汇总候选方案 → 其他分身分别确认
→ 系统保留共识与分歧 → 🔐 你最终决定
→ 主笔只在独立 Git worktree 中修改 → 其他成员只读验证
→ 系统执行批准时展示的 check/test 脚本并保存退出码 → 其他成员只读复核
→ 服务端生成文件清单、检查证据和补丁指纹 → 🔐 你再次决定是否交付
→ 批准后才把补丁套用到正式工作区
```

**共识机制**：
- 提案与审查必须符合 `schemaVersion: 1` 的 JSON 合同，格式错误只允许一次有界修复
- 每个确认者即使声明批准，只要仍有问题、缺失证据或未通过检查，服务端仍会拒绝该票
- 未达成机器共识时，系统不会假装一致，而是显示完整分歧；你必须显式确认“了解分歧，仍继续”

**闸门系统**：
- **人工确认是默认且强制的**：讨论完成后暂停，展示方案和可靠性摘要，你可以确认执行、修改目标或取消
- 即使旧配置启用了 `ALLOW_AUTO_GATE=true`，隔离实施和最终交付仍会降级为人工确认
- 确认时后端只信任服务端保存并计算过哈希的方案，浏览器不能替换方案内容
- 真实执行只支持状态干净的 Git 项目；没有工作目录、不是 Git、存在未提交修改或零文件变化都不会报告成功
- 主笔写入独立 worktree，其他成员保持只读；只有第二次人工批准才交付到正式目录，且不会自动提交 Git、发布或部署
- 任一独立验证者给出 `fail`、`unknown`、必须修复项或高危残余风险时，任务进入“待修订”，不会显示完成
- Node 项目会在方案闸门展示 `package.json` 中的 `check`/`test` 脚本原文；批准后系统在隔离 worktree 中实际执行并保存退出码、耗时和脱敏输出。非零退出、超时或脚本被 AI 修改都会阻止交付
- 没有配置受支持检查的项目仍可由 AI 复核，但界面会明确标记“仅 AI 复核”，不会声称自动化测试已经通过

### 🔄 多任务并行
- 每个 AI 请求在后台独立运行，不阻塞界面
- 一个任务在思考时，可以随时创建新任务、切换到其他任务
- 侧边栏显示绿色脉冲点 🟢 标识正在后台运行的任务
- 顶部状态栏显示当前有多少个任务在进行中
- 切回正在运行的任务时，自动恢复思考动画和协作进度
- 浏览器刷新或短暂断线不会取消后台 AI；页面会按运行事件序号续接
- 服务重启后，对话投递可以自动恢复；长程协作会保留检查点并安全停止，等待重新发起

### 📜 智能体轨迹（避免黑箱）
- 顶栏「📜」按钮打开右侧轨迹侧栏，按“运行 → Provider 调用 → 具体动作”还原实际执行顺序
- Claude Code：记录工具开始与结果、读写路径、命令、错误、轮数、Token 与耗时
- Codex：记录命令开始与退出码/输出摘要、文件修改、网络/MCP 调用、Provider 提供的推理摘要和 Token
- DeepSeek Harness：为每次调用建立隔离的原始 SessionEvent 日志，实时读取 step、tool/call、tool/result、usage、retry 和异常 turn/end；读取完成后立即删除临时原始日志
- 轨迹事件先脱敏、限长，再写入本项目的持久事件库；刷新、切换任务和页面断线后可按运行分页恢复
- 支持关键词搜索与命令、文件、工具、失败筛选；点开动作可查看结构化输入、结果、耗时、错误和记录来源
- 只展示 Provider 明确提供或确定性代码实际观测到的事实；不会伪造或泄露隐藏思维链，Provider 未提供时会明确标记“细节受限”

### 🧠 Context Tree 团队记忆
- 用户可以添加项目目标、约束、决定、架构和经验节点
- 只有用户批准的节点会进入后续对话、讨论、实施和验证
- 每次运行记录实际使用的节点 ID 和摘要哈希，便于追溯
- AI 形成的方案和交付经验只能生成“待审核建议”，不能自行写成团队事实

### 🗂️ 任务管理
- 每个任务独立保存，互不干扰
- 自动命名（取你第一句话的前 20 个字）
- 支持随时删除
- 任务列表按最后活跃时间排序

## 🏗️ 技术架构

### 技术选型
- **后端**：Node.js 原生 `http` 模块
- **前端**：纯原生 HTML + CSS + JavaScript（无框架）
- **AI 接口**：通过 `child_process.spawn()` 调用本地安装的 Claude CLI、Codex CLI 和 DeepSeek Harness（dsh headless）
- **实时通信**：SSE（Server-Sent Events）用于对话与协作的实时状态和逐成员结果
- **可靠控制面**：Node 内置 SQLite，保存运行、投递、事件、成员、Context Tree 和隔离工作区记录
- **兼容任务投影**：`sessions/*.json` 继续保存易读的任务与对话，逐步迁移而不破坏旧数据

### 架构图
```
浏览器 → 薄 HTTP 路由 → 运行/编排模块 → Provider 适配器 → Claude/Codex/dsh CLI
                         ↓
                  SQLite 可靠控制面
             （运行、收件箱、事件、记忆、工作区）
                         ↓
          JSON 任务投影 + Git worktree 隔离产物
```

### 数据流

**对话模式**（SSE 实时、多成员可部分成功）：
```
用户输入和防重复编号 → SQLite 创建运行与投递 → 后台 worker 领取
→ spawn Claude/Codex/dsh → 先持久化结果再确认投递 → SSE 按事件序号推送
→ 可选双方互证 → 刷新后续接；重复提交只重放同一运行
```

**协作模式**（SSE 流式，多轮对话）：
```
用户输入目标 → POST /api/collaborate → SSE 连接建立
→ 第 1 轮：所有分身独立回答，不读取其他成员答案
→ 第 2—5 轮：从持久收件箱领取定向消息，回答后确认投递
→ 用户指定主笔汇总 → 其余分身独立确认
→ 第一次人工闸门确认方案
→ Git worktree 隔离实施 → 其他成员分别按验收标准独立验证
→ 第二次人工闸门确认补丁交付；否则丢弃，正式工作区保持不变
→ SSE 连接关闭
```

## 🚀 快速开始

日常运行不需要安装开发工具依赖：工作台运行时代码只使用 Node.js 内置模块。安全扫描工具按需运行，不需要把 `node_modules/` 长期保留在项目目录。可以运行 `npm run package:check` 和 `npm run release:check` 检查轻量发布清单；`sessions/`、`.workbench/`、`node_modules/`、`.claude/` 和本地凭据不会进入公开仓库或发布包。

### 前置条件
确保你的电脑已安装：
1. **Node.js**（v22.13 或以上；本项目与 Codex Security 使用同一最低版本）
2. **Claude CLI**（`claude` 命令可用）
3. **Codex CLI**（`codex` 命令可用）
4. **DeepSeek Harness**（`dsh` 命令可用，且 headless profile 已初始化；首次使用可先运行 `dsh --profile headless "hi"` 确认可用）

### 启动步骤

1. 从 GitHub 获取项目并进入目录：
   ```bash
   git clone <你的 GitHub 仓库地址>
   cd future-is-here-workbench
   ```

2. 检查环境（可选 Provider 缺失不会阻止工作台启动）：
   ```bash
   npm run doctor
   ```

3. 启动服务器：
   ```bash
   npm start
   ```

4. 浏览器打开：
   ```
   http://localhost:3456
   ```

5. 开始使用——点击「➕ 新建任务」即可。

### 关闭服务
在终端按 `Ctrl + C`

### 开发检查

```bash
npm run check        # 检查所有后端 JavaScript 语法
npm test             # 运行回归测试
npm run security:scan # 使用 Codex Security 扫描当前项目
npm run release:check  # 检查开源边界和私密目录
```

Codex Security 是开发期工具，不会在产品启动时加载。官方 CLI 当前要求 Node 22.13+、24.x 或 26.x；它通过 `npx` 按需运行，避免把约 419MB 的开发依赖长期放在项目目录里；业务运行时仍保持轻量。

### 开源使用边界

- GitHub 仓库只提供程序、测试和文档，不提供任何 AI 账号、API Key 或云端服务。
- 每位使用者都应在自己的 Mac 上安装和登录自己的 Claude CLI、Codex CLI 或 DeepSeek Harness。
- 默认服务只监听 `127.0.0.1`，仅当前电脑可以访问。
- 不要把 `HOST=0.0.0.0` 当作“让别人使用”的方式；当前版本没有 HTTPS、账号系统和多用户隔离。
- 对话、轨迹、上传资料、备份和工作区都保存在使用者自己的电脑上。
- 公开提交代码前运行 `npm run release:check`，确认没有私密运行目录或个人配置。

### 监听地址与访问令牌

默认只监听 `127.0.0.1:3456`。如果确实要让其他设备访问，必须显式设置令牌：

```bash
HOST=0.0.0.0 WORKBENCH_TOKEN='请替换成高强度随机字符串' npm start
```

浏览器会在第一次收到 `401` 时询问令牌，并只保存在当前标签页的 `sessionStorage` 中。没有令牌时，程序拒绝监听非本机地址。

## 📖 使用指南

### 基础对话
1. 点击左侧「➕ 新建任务」
2. 点击 Claude、Codex、DeepSeek（dsh）按钮组成当前对话名单，也可以点击“全选”
3. 选择两个及以上 AI 时，再选择“互相确认（更可靠）”或“独立并行（更快）”
4. 在输入框输入内容，按 Shift+Enter 发送（Enter 换行）；任务运行中按 Esc 可终止
5. 页面分别显示每位成员的状态；任意一方先完成就立即展示并持久化

### 发起协作
1. 在工作区命令栏输入 `cd /完整/项目路径`，先绑定本次任务允许操作的目录
2. 点击顶部「🤝 协作」切换到协作模式；如果只想先讨论，选择「🧭 方案讨论」
3. 选择会议方法（共创/审查/对抗/分工）
4. 在“本次 AI 团队”中添加或删除 Claude/Codex/DeepSeek 分身；底层 Provider 选择只对你可见
5. 为每个成员填写会议姓名、本次临时角色和重点关注，并选择主笔、讨论轮数和共识规则
6. 输入任务目标，观察独立思考、定向提问、回应和质疑
7. 方案讨论可以一键导入协作；协作任务必须由你确认后才会真实写入工作区

工作区命令栏只支持 `pwd`、首次绑定时的 `cd <目录>` 和 `ls [目录]`。绑定成功后，该任务的工作目录永久锁定，`ls` 也不能越出锁定目录。这些命令由服务端直接解析文件路径，不经过 shell。

文件夹按钮不是选择工作区，而是上传参考资料。页面不会把 100MB 文件转成 Base64 塞进 JSON；它会顺序上传 4MB 小块，断线后重新选择同一文件夹可续传。页面会分别显示“本任务已保存多少”与“本轮实际引用多少”。扫描版 PDF 会在本机按页数、超时和输出大小限制进行 OCR；如果本机没有 `pdftoppm` 或 `tesseract`，会明确标为解析失败，不会假装成功。

### 输入框命令

- `/help`：显示命令清单
- `/new` 或 `/clear`：经确认后清空当前任务的对话、轨迹、运行记录、图片、参考资料和应用缓存；保留已锁定工作目录、正式项目文件和已批准团队记忆
- `/status`：查看模式、工作目录、消息数与存储占用
- `/context`：查看下一轮 AI 实际会继承的上下文范围
- `/pwd`、`/ls [子目录]`：只读查看已锁定工作目录
- `/files`：查看当前任务参考资料

输入框不支持 `!`、管道、重定向或任意 shell 命令。

### 轻量存储原则

- “轻量”是工程方向，不会据此缩短会话、删减轨迹、降低参考资料能力，或牺牲安全与恢复能力。
- 会话 JSON 只去掉排版空白；SQLite 中较大的结构化状态使用可逆 gzip，读取后的内容、顺序和轨迹回放保持一致。
- SQLite 继续使用完整同步事务和 WAL；尾日志自动检查点并限制为约 1MB，不能用省空间换取写入安全。
- 诊断日志只保留当前文件和一份轮换备份，每份最多 1MB；日志不写请求正文、令牌或完整 AI 输出。
- 每 15 分钟只清理工作台目录内超过 1 小时的崩溃临时文件，以及超过 24 小时的未完成参考资料；不会扫描或删除正式项目文件。
- 总占用达到 500MB 时只在 `/status` 明确提醒，不会静默删除用户历史。`/new` 和永久删除仍由用户最终决定。

### 多任务并行
1. 在任意任务中发送消息或发起协作
2. **不需要等待**——直接点击「➕ 新建任务」或切换到其他任务
3. 后台运行的任务会在侧边栏显示 🟢 绿点
4. 切回该任务时，AI 已完成的内容会完整呈现

### 任务管理
- **切换任务**：点击侧边栏的任务项
- **永久删除任务**：鼠标悬停在任务项上，点击 🗑 垃圾桶图标并确认；会删除任务记录、运行记录、图片、参考资料和任务专属隔离产物。正式工作目录、项目代码和已批准团队记忆不会被删除，此操作不可恢复。
- **收起侧边栏**：点击左上角 ☰ 图标

## ⚖️ 智能体行为准则

工作台中的所有智能体（Claude、Codex、DeepSeek）在对话、互证、协作、执行和验证的每一份提示词中都遵守以下两条铁律：

1. **指令执行铁律**：用户消息（尤其是最新一条）中的明确要求——字数限制、输出格式、语言、范围、风格——是最高优先级指令，必须逐条严格执行；提交回答前自查一遍是否全部满足，不满足就先改再交。
2. **客观实际铁律**：以客观实际为第一准则，有理有据；不迎合、不顺从用户的立场。对就是对，错就明确指出错在哪里，证据不足就直说不足。宁可指出问题得罪人，不用漂亮话掩盖事实。

配套的运行机制：

- **思考强度自适应**：闲聊级短消息自动使用低思考档（省 token、省等待）；普通问答与协作讨论使用 CLI 默认档；隔离执行（写代码/调试）自动使用高思考档。
- **Provider 与个人配置隔离**：Claude 调用通过 `--setting-sources project` 与用户全局设置隔离，联网凭据由服务端显式注入；`--setting-sources` 管不到的 CLAUDE.md 记忆文件（如全局导师人设）由 `--append-system-prompt` 的末位覆盖指令压掉（与 Codex 的 `--ignore-user-config` 对齐）。dsh 继续使用隔离的 headless profile。

## 🔒 安全设计

当前版本会校验可信 Host/Origin、隔离各 Provider 的凭据环境、限制 Provider 队列和 SSE 连接，并把“确认方案”绑定到方案与 Context Tree 指纹，把“交付”绑定到执行运行、worktree、Git 基础版本和补丁指纹。真实执行必须从 Git 项目根目录启动；选择仓库子目录时会提示切换到实际 Git 根目录。

本项目经过了多轮安全审查，关键措施如下：

| 威胁 | 防护措施 |
|------|---------|
| **Shell 命令注入** | 用户文本不会进入 shell；Provider 使用参数数组启动。项目检查只允许方案闸门展示并绑定指纹的 `npm run check` / `npm test`，不接受 AI 临时生成的任意命令 |
| **路径遍历攻击** | 会话 ID 严格校验 `/^\d+$/`（纯数字），拒绝非法字符 |
| **XSS 跨站脚本** | 所有 AI 返回的 Markdown 经 DOMPurify 消毒后才插入 DOM |
| **服务崩溃** | 请求体有大小限制，畸形 JSON 和 `null` 会返回 400，不会让服务进程退出 |
| **请求挂起** | 静态文件不存在时返回 404，客户端断开时正确关闭连接 |
| **无限循环** | 单任务最多 6 个分身、5 轮交叉对话，格式修复也只有一次 |
| **会话 ID 冲突** | 时间戳 + 6 位随机数，并检查文件冲突 |
| **并发覆盖** | JSON 投影使用进程内写锁和原子替换；SQLite 用事务、唯一键和投递租约保护可靠运行，重启后回收未确认工作 |
| **危险 AI 操作** | 讨论阶段保持只读；批准执行后仅主笔进入独立 Git worktree，Codex 使用 workspace-write、Claude 使用 acceptEdits；从不使用危险绕过参数 |
| **任意命令注入** | 网页命令栏只实现确定性的 pwd/cd/ls，不调用 shell，不支持管道、重定向或任意命令 |
| **工作区越界** | 真实路径必须位于允许根目录内，符号链接经过 realpath 后再次校验；执行前必须人工确认具体路径 |
| **伪执行成功** | 服务端比较执行前后文件清单；没有真实文件变化时任务直接进入验证失败 |
| **虚构测试通过** | 系统在隔离 worktree 中实际执行已批准的检查脚本，保存退出码、耗时和脱敏输出；AI 的 `pass` 不能覆盖失败或超时 |
| **AI 幻觉授权** | 模型输出经过结构校验；问题、缺失证据、未知检查和高危残余风险由确定性代码阻断 |
| **假冒团队成员** | 每条定向消息都校验目标实例 ID；不能发送给自己或不存在的分身 |
| **会议身份泄漏** | Provider 内部 ID 与会议成员 ID 分离；提示词只使用 `member-N`、会议姓名和岗位，旧技术名称会转换为中性姓名 |
| **分身资源放大** | 最多 6 个分身、5 轮对话；Provider 全局队列默认最多同时运行 4 个子进程 |
| **环境变量泄露** | Provider 子进程只继承明确允许的环境变量，不再复制服务进程的全部环境 |
| **会话隐私** | 服务启动和访问时强制目录 `0700`、会话文件 `0600`，包括旧文件权限迁移 |
| **未授权远程调用** | 默认回环监听；非回环监听必须设置 `WORKBENCH_TOKEN`，API 使用 Bearer 令牌 |
| **跨站请求伪造** | API 校验浏览器 `Origin` 必须与当前服务地址一致；无 `Origin` 的 CLI 调用仍受监听地址/令牌策略约束 |

## 🧠 核心设计理念

### 为什么用 `spawn()` 而不是 `exec()`？
`exec()` 会先把整段文本交给系统 shell，用户文本中的特殊字符可能被解释成命令。Provider 调用使用 `spawn()` 和固定参数数组，因此用户提示词不会被当作 shell 语句执行。需要注意：`npm run` 本身会按照项目的 `package.json` 执行脚本，所以系统只允许闸门中已展示、已绑定指纹的 `check`/`test`；脚本内容在批准后变化就会停止验证。这降低了命令替换风险，但不是操作系统级沙箱。

### 为什么用 SSE 而不是 WebSocket？
SSE（Server-Sent Events）是单向的——服务器推送给浏览器，这对协作模式足够了。它比 WebSocket 更简单，不需要额外的握手协议和第三方库，完美契合"零依赖"的设计原则。

### 为什么现在同时使用 SQLite 和 JSON？
JSON 仍适合充当“容易阅读的任务档案”，但不能可靠表达消息领取、确认、重试和并发状态。SQLite 像事务账本，负责必须原子成立的运行控制；JSON 像可读副本，继续兼容已有任务。两者并行迁移，避免一次性破坏旧数据。

### 多任务并行怎么实现的？
浏览器用以下本地状态显示多个任务，但真正的运行事实以 SQLite 为准：
- `busySessions`（Set）：记录哪些任务正在忙
- `activeThinkers`（Map）：记录每个任务当前谁在思考、什么角色
- `pendingGates`（Map）：记录哪些任务在等用户确认闸门

这样每个任务的状态独立追踪，互不阻塞。

## ❓ 常见问题

**Q：AI 回复特别慢怎么办？**
A：单次 AI 调用按阶段分级限时：交互式对话 180 秒（`CHAT_PROVIDER_TIMEOUT_MS`）、协作讨论 240 秒（`COLLAB_PROVIDER_TIMEOUT_MS`）、隔离执行（写代码/调试）600 秒（`EXECUTION_PROVIDER_TIMEOUT_MS`）、其他调用 180 秒（`PROVIDER_TIMEOUT_MS`）。经中转网关调用 Claude 时，仅等待第一个字就可能耗费 7—9 秒，属通道固有延迟。聊天失败不会偷偷重复等待，用户可直接重新发送；Provider 状态栏只检查 CLI 命令能否启动，不代表账号、额度和真实调用一定可用。健康接口会显示当前进程内的成功率和 p50/p95 延迟。

**Q：Codex 报错或额度用完了怎么办？**
A：检查 Codex CLI 登录状态和额度。协作模式不会跳过审查失败：审查失败会停止在执行前，避免把未经审查的方案继续往下传。

**Q：dsh（DeepSeek）不可用或报 TRANSPORT 错误怎么办？**
A：先运行 `dsh --version`；如果终端显示找不到命令，说明它尚未安装，页面会禁用单独选择并在“多 AI”中自动跳过。安装后再运行 `dsh --profile headless "hi"` 确认 headless 通道可用；凭据由 DeepSeek Harness（`~/.dsh`）管理。若返回 `TRANSPORT: Stream ended without finish_reason`，请保持 `DSH_MODEL=deepseek-chat`（dsh 0.1.0-rc.6 对 `deepseek-v4-flash` 的已知问题）。服务会自动按 `DSH_CLI_PATH` → PATH → `~/.npm/_npx/*/node_modules/.bin/dsh` 的顺序定位 dsh（即使服务进程的 PATH 不含 npx 目录也能找到），仅当三者都失败时才需要手动设置 `DSH_CLI_PATH` 指向完整路径。

**Q：数据存在哪里？怎么备份？**
A：可读任务和对话在 `sessions/`；可靠运行、收件箱、事件、Context Tree 和隔离工作区登记在 `.workbench/state.sqlite3`。在对话框输入 `/backup` 可创建一份带完整性校验的恢复快照，系统最多保留两份，已完成的大资料使用硬链接避免重复占用空间；输入 `/backups` 查看编号，输入 `/restore <编号>` 并确认后，系统会安全停止并在下次启动前恢复。上传、解析、AI 运行或隔离产物未结清时会拒绝备份，避免保存半成品。

**Q：别人能直接使用我电脑上的服务吗？**
A：当前不建议这样做。开源项目的设计是每个人在自己的 Mac 上运行自己的服务和 AI 账号。远程多用户访问需要 HTTPS、账号、权限、隔离工作区和审计系统，将在本地能力稳定后另行开发。

**Q：服务重启或删除任务后，后台正在运行的 AI 怎么办？**
A：普通对话会根据未确认投递自动恢复，不依赖原浏览器连接。多轮讨论或隔离执行在进程重启时会安全停止，已完成的消息和检查点仍保留，但需要人工重新发起；运行中的任务必须先点击“终止”，之后才能删除。删除任务时会自动丢弃该任务尚未交付的隔离产物。

**Q：如何修改协作模式的提示词？**
A：`src/modes.js` 只维护会议方法，任务角色由前端团队配置；`src/collaboration.js` 负责动态会议和定向消息，`src/ai-contract.js` 维护结构化协议。任何协议变更都必须升级提示词版本并补回归测试。
