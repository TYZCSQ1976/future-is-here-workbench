# 可写执行使用持久化防重放栅栏

工作台在调用拥有工作区写权限的 Provider 前，必须先在 SQLite 中原子记录执行栅栏。栅栏绑定运行编号、原任务编号、方案指纹、上下文指纹、执行者和隔离工作区；同一次运行只允许首次放行，后续调用一律拒绝。

栅栏只在隔离产物被正式交付、明确丢弃，或确认没有变化并完成回收后结清。若服务在中途重启，未结清的可写运行进入 `interrupted`，保留隔离产物并禁止自动重放，由用户检查后决定交付或丢弃。普通只读协作仍可恢复到队列。

这个方案故意偏保守：当前 Provider 适配器不能逐条回传工具副作用，所以系统只能在调用前设栅栏，无法判断崩溃发生时 Provider 是否真的写过文件。代价是少量“可能尚未写入”的执行也需要人工处理；收益是不会为了追求自动恢复而重复执行一次不确定的写操作。未来只有在 Provider 提供可信的工具事件和幂等凭据后，才考虑把栅栏缩小到单个副作用级别。
